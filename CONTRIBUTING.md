# Contributing

Contributions should make an integration more reproducible, safer, or more useful without advertising TARX inside an upstream project.

A change should include:

- A bounded problem statement.
- Exact dependency versions.
- A test or reproducible verification path.
- Minimum provider scopes and event subscriptions.
- Explicit credential, data, and approval boundaries.
- An honest status label.

Do not add provider logos, copied vendor marketing text, credentials, private TARX implementation details, or an integration claim backed only by catalog metadata.
